# Job Change Predictor

Predicts the probability that a data scientist candidate is looking for a
new job, based on the [HR Analytics: Job Change of Data Scientists](https://www.kaggle.com/datasets/arashnic/hr-analytics-job-change-of-data-scientists)
dataset. Trained with Logistic Regression, Random Forest, XGBoost,
LightGBM, and CatBoost, and served through a Streamlit form.

## Project structure

```
.
├── app.py              # Streamlit web app (the deployed UI)
├── train_model.py      # Trains the model and saves model.pkl / model_meta.pkl
├── preprocessing.py     # Shared preprocessing logic (used by both files above)
├── requirements.txt    # Python dependencies
├── aug_train.csv       # Training data (not included in this repo — see below)
├── model.pkl            # Saved trained pipeline (generated by train_model.py)
└── model_meta.pkl       # Saved metadata: threshold, known cities, medians (generated by train_model.py)
```

## Setup

1. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

2. Place `aug_train.csv` in this folder (get it from the
   [Kaggle dataset page](https://www.kaggle.com/datasets/arashnic/hr-analytics-job-change-of-data-scientists) —
   not included in this repo since it's third-party data).

3. Train the model (only needs to run once; produces `model.pkl` and `model_meta.pkl`):
   ```bash
   python train_model.py
   ```
   This runs a hyperparameter search across all five model types and keeps
   whichever one scores best on PR-AUC. Takes anywhere from a few minutes to
   ~30 minutes depending on your machine.

4. Launch the app:
   ```bash
   streamlit run app.py
   ```

## How it works

- **`preprocessing.py`** holds all the feature engineering (missing-value
  handling, `experience`/`last_new_job` string-to-number conversion, the
  `city` frequency encoder, engineered features like
  `experience_to_last_job_ratio` and `cdi_bin`). Both training and inference
  import from this file, so the exact same transformations are applied at
  both stages — this is what prevents training/serving skew.
- **`train_model.py`** builds the full scikit-learn pipeline, runs
  `RandomizedSearchCV` per model (optimizing directly for PR-AUC), picks a
  decision threshold that maximizes F1 on a held-out validation split, and
  saves the winning pipeline + metadata.
- **`app.py`** loads the saved pipeline, presents a form for each raw input
  feature, and returns the predicted probability plus a stay/leave call
  based on the tuned threshold.

## Deploying online (free)

See [Streamlit Community Cloud](https://streamlit.io/cloud): connect this
repo, point it at `app.py`, and deploy. Note `model.pkl` and
`model_meta.pkl` need to be committed to the repo (or otherwise available
at runtime) since Community Cloud won't run `train_model.py` for you.

## Notes / limitations

- PR-AUC on the validation split is in the ~0.55–0.58 range across models —
  modest but expected for this dataset (positive class prevalence is ~25%,
  so this is roughly 2x better than random guessing). This is a genuinely
  noisy, low-signal dataset; see the model comparison output from
  `train_model.py` for exact numbers on your run.
- `city` is frequency-encoded rather than one-hot encoded due to high
  cardinality (123 unique values in training data).
- Unknown/unseen cities at prediction time get a frequency of 0 (fall back
  to being treated as rare).
